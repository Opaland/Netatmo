## 11. Évaluation de l'écran Réglages (S-8.4, à vérifier)

**Ce qui est bien pensé.** Le chiffrement *sealed box* avec la clé publique du dépôt est la méthode
documentée par GitHub : le navigateur ne peut que **écrire**, jamais relire un secret, et GitHub ne voit
la valeur qu'après déchiffrement côté Actions. Le jeton reste en mémoire : un vol du téléphone
verrouillé ne le donne pas. Il remplace une manipulation pénible sur le site GitHub mobile.

**Les compromis.**

| Risque | Analyse pour ce projet |
|---|---|
| Jeton dans le navigateur | Pendant la session, n'importe quel script de la page peut le lire. Avec `Secrets: write` + `Actions: write` (noms exacts des permissions à vérifier), un attaquant peut remplacer `INTUIS_*` ou `ENEDIS_TOKEN` par des valeurs piégées, ou lancer le workflow. Il ne peut pas **lire** les secrets existants. Si le jeton a aussi `Contents: write`, il peut modifier le code du collecteur et exfiltrer tous les secrets au prochain run : **portée à refuser**. |
| Portée | Un jeton fine-grained limité à `Opaland/Netatmo` borne les dégâts à ce dépôt ; un jeton *classic* `repo` donnerait accès à tous les dépôts du compte. |
| XSS | `main.ts` construit l'interface par `innerHTML` (protégée par `esc()`, et `markdown.ts` échappe tout) ; les données affichées viennent de fichiers chiffrés par le propriétaire, donc peu exposées. Mais il n'y a **aucune CSP** dans `web/index.html`, et GitHub Pages ne permet pas d'en-têtes HTTP : seule une CSP en `<meta>` est possible (`frame-ancestors` y est ignoré). |
| Chaîne d'approvisionnement | libsodium (paquet npm `libsodium-wrappers` ou équivalent, à vérifier) embarque du WebAssembly difficile à relire ; une version compromise publiée sur npm passerait par une PR Dependabot. Les autres dépendances runtime (ECharts, Workbox via `vite-plugin-pwa`) partagent la page : elles verraient aussi le jeton. |
| Erreur de manipulation | Écrire un nouveau `DATA_PASSPHRASE` sans `rekey` rend `Store` incapable de lire les `*.enc.json` existants : la collecte suivante échoue (lecture de `collector/storage.py`). |
| Bouton « lancer la collecte » | Des relances rapprochées sollicitent l'API Intuis (persona 45) et se mettent en file (`concurrency: collect`). |

**Garde-fous concrets (à mettre dans les critères de S-8.4 / S-8.5 / S-8.6).**

1. **Jeton minimal et court.** Le guide intégré impose : fine-grained, dépôt unique, `Secrets` et
   `Actions` en écriture, `Contents` **non coché**, expiration ≤ 7 jours. Au collage, l'appli appelle
   l'API et refuse un jeton qui a accès à plus d'un dépôt ou à `contents` (faisabilité à vérifier via les
   en-têtes de réponse). Champ `type="password"`, `autocomplete="off"`, jeton effacé de la mémoire au
   verrouillage, à la mise en arrière-plan et 10 min après la dernière écriture ; jamais dans
   `localStorage`, IndexedDB ni le cache du service worker.
2. **CSP en `<meta>`** : `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; connect-src 'self'
   https://api.github.com; object-src 'none'; base-uri 'none'; form-action 'none'` (compatibilité avec
   l'enregistrement du service worker de `vite-plugin-pwa` à vérifier). Test CI : le build échoue si
   `index.html` perd la CSP.
3. **libsodium sous contrôle** : version exacte (sans `^`) dans `package.json`, `npm ci` sur
   `package-lock.json`, **import dynamique** uniquement à l'ouverture de Réglages (hors bundle principal),
   aucun CDN, et un test Vitest qui chiffre puis ouvre une *sealed box* avec une paire de clés de test.
   Les PR Dependabot sur ce paquet ne sont jamais fusionnées automatiquement.
4. **Liste fermée de secrets** : Réglages n'écrit que `INTUIS_*`, `NETATMO_*`, `ENEDIS_*`,
   `ANTHROPIC_API_KEY` ; `DATA_PASSPHRASE` est refusé et renvoie vers `rekey` (S-8.6). Confirmation avant
   d'écraser un secret existant, affichage des seuls noms + `updated_at`.
5. **Bouton de collecte bridé** : désactivé si un run `collect` est en cours ou a démarré il y a moins
   d'une heure ; l'issue d'alerte et le résumé de job (S-1.4) gardent la trace des lancements manuels.
